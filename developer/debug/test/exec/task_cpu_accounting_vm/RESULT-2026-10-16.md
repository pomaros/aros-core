# CPU21 actual guest qualification

**PASS for Apple task CPU accounting in the generic UP VM.** The real public
`task.resource` query workload passes; disabling the actual dispatch-accounting
producer makes the same executable fail for zero counters. No SMP, physical
Apple hardware or actual system-sleep accounting acceptance is claimed.

Production accounting is frozen at `c3cbe0a55e`; the final production probe is
`bccfc6242b`. Positive validation source is `6348f797c23248cb9759db034433b869c9c4bf8c`
on `codex-apple-task-cpu-vm`. The validation-only headless boot hook supplies owned
NIL streams and runs `SYS:CPUPROBE` after the existing ABI proof. The workload
uses `LockTaskList`, `NextTaskEntry` and `QueryTaskTagList`, never private counter
fields. Host/native evidence remains in
[the native report](../../kernel/apple_task_cpu_host/RESULT-CPU-2026-10-16.md).

The oracle requires meaningful busy time/usage, low idle usage, monotonic CPUTime,
upper bounds against observed elapsed time plus 10 ms sampling overhead, and
agreement between measured CPU fraction and reported usage within five percentage
points. Seven host oracle tests reject zero/inflated counters, wrong usage,
missing/nonempty traces, crashes after proof, incorrect firmware exceptions and
unrelated negative-control failures. Those synthetic tests are separate from the
actual guest result above.

## Actual disabled-producer control

`cpu-accounting-validation/attempt-004-negative/tcg-01` deliberately retains a
**FAIL** feature verdict. Validation-only commit `6aab14388766675fd398b5dfa2d66142d627a32f`
replaces `AppleTaskDispatch` with a no-op. The exact patch is retained alongside
the negative artifacts and in this directory; it is not part of the production
or positive validation branch.

The worker executes 656,831,885 iterations over a 1,006,027 µs busy window and a
1,009,350 µs idle window, while all six baseline/busy/idle CPUTime and CPUUsage
values are zero. The probe rejects the busy/idle contract, its caller rejects the
command, and stage-two rejects startup. These exact expected failures are observed
for 3.054301750 seconds; unrelated faults are not exempted. QEMU exits normally
through QMP with an empty trace. The independent negative-control assertion passes;
the disabled feature itself does not.

The positive and negative images contain the **same CPUPROBE and SYS.img bytes**.
Among shared module/build-input paths, only `kernel.resource` differs; the
resulting ESP `GEN0.BND` and `BOOT0.ID` consequently differ too. The complete
module/input comparison is retained in results.json. This checks the
real producer, rather than replacing query results or weakening the oracle.

## Retained failures and provenance

- Initial boot build `cpu-boot-01.log` retains the already corrected private
  `AROSAppleRuntimeLocal` link failure. The frozen runtime removes that cross-module
  reference; subsequent boot builds pass.
- Attempt 001 stops before AROS at stock EDK2 diagnostics under the obsolete UART
  runner. The current runner uses the canonical ACPI/virtio console configuration
  and preserves/scans firmware.log. Only the four exact, known early Image errors
  and the exact TPM diagnostic are allowed before the first AROS loader marker;
  unknown or late failures still fail.
- Attempt 002 reaches RunCommand but times out before main. Source inspection
  identifies `compiler/autoinit/fromwb.c`: a bootstrap process without `pr_CLI`
  waits for a Workbench startup message that this fixture never sends. The probe
  now uses the same `__nowbsupport`, `__nostdiowin`, `__nocommandline` and WBenchMsg
  convention as existing headless probes. This was a harness startup defect,
  not an accounting defect.

Both actual runs retain complete raw serial, firmware, host and empty trace files,
registers, timed QMP exchanges, exact immutable/copied ESP membership and hashes,
and a FAT roundtrip proving the embedded CPUPROBE executable. Root independently
replayed both, retaining `root-replay.json` and logs. The interactive demo PID 22219
was present and untouched. Launch-time process snapshots showed no other automated
QEMU, but they cannot exclude a run between snapshots. A later HVF disclosure
required the explicit timing audit and reserved replay below; the earlier blanket
claim of no concurrent automated guest is withdrawn. Thresholds were not relaxed.

[results.json](results.json) pins the artifacts, source revisions and hashes.
The collector/package instructions are on the positive validation branch in
`developer/debug/test/exec/task_cpu_accounting_vm/README.md`. The normal source
branch and build outputs are restored after the negative control.

cannot exclude an unobserved shorter process; the explicit board reservation
provides the coordination boundary.
